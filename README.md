# کیا — KIYA

فروشگاه اجتماعی فارسی با هویت بنفش/طلایی: ویترین اجتماعی، حساب مشتری، سبد سروری، سفارش اولیه با رزرو، پنل مدیریت با MFA و پنل پردازش سفارش.
دامنهٔ هدف: `kiyaco24.ir` · وضعیت: **نسخهٔ 0.12.0 — در حال تکمیل، انتشار تولید انجام نشده**

> **پرداخت آنلاین، هزینهٔ ارسال و مرجوعی هنوز فعال نیستند.** سفارش‌های فعلی «سفارش اولیه» هستند: موجودی را کوتاه‌مدت رزرو می‌کنند و هیچ وجهی دریافت نمی‌شود. متن حقوقی صفحات عمومی پیش‌نویس است و باید توسط مالک تأیید شود.

**برای دیدن پنل بدون رمز:** مسیر `/admin/preview` یا لینک «دیدن مدیریت فقط‌خواندنی»؛ صرفاً رابط فقط‌خواندنی با نمونه‌های محلی است، نه ورود مدیر یا نمایش اطلاعات خصوصی. `/admin` همچنان رمز و MFA شخصی می‌خواهد.

## نقشهٔ سریع مسیرها

| مسیر | چیست |
|---|---|
| `/` | فید اصلی ویترین (پست، استوری، جست‌وجو، سبد نمونهٔ محلی) |
| `/explore` `/saved` `/profile` `/cart` `/inbox` `/account` | بخش‌های ویترین اجتماعی، ذخیره‌شده‌ها، پروفایل برند، سبد نمونه، راه‌های ارتباط، حساب مشتری |
| `/wholesale` | پورتال همکاری و قیمت خصوصی (فقط برای حساب تأییدشده) |
| `/p/[id]` | صفحهٔ مستقیم کالا (پست باز‌شده با URL قابل اشتراک) |
| `/basket` | سبد سروری واقعی، محاسبهٔ قیمت، ثبت سفارش اولیه، تاریخچه و لغو رزرو |
| `/about` `/faq` `/shipping` `/terms` `/contact` | صفحات عمومی اطلاعاتی و حقوقی (پیش‌نویس) |
| `/admin` | ورود پرسنل با رمز + TOTP سپس داشبورد، **سفارش‌ها و رزرو**، کاتالوگ و موجودی، همکاران، تیم و دسترسی‌ها، audit |
| `/admin/preview` | نمایش فقط‌خواندنی رابط مدیریت، بدون نشست یا مجوز سروری |
| `/progress` | نقشهٔ نسخه‌دار تکمیل پروژه داخل سایت |

## اجرای محلی

Node.js 22 و npm، در دو ترمینال:

```sh
npm ci
npm run db:local
```

ترمینال دوم، پس از پیام آماده‌بودن PostgreSQL:

```sh
npm run db:migrate
npm run db:seed
npm run dev -- --port 3000
```

`db:local` یک **PostgreSQL واقعی** از باینری npm اجرا می‌کند (نه SQLite)، فقط روی `127.0.0.1:55432`. داده در `.data/postgres` و اسرار تصادفی در `.env.local` ذخیره می‌شوند؛ هر دو از Git خارج‌اند. اگر `.env.local` از قبل وجود دارد آن را بدون بررسی پاک نکن؛ قالب متغیرها در [.env.example](.env.example) است.

برای خروجی تولیدیِ **همین محیط آزمایشی**: `npm run build` سپس `npm run start -- --port 3000`. وب‌سرور به `0.0.0.0` متصل می‌شود و previewهای `e2b.app` مجازند؛ مرورگر برای APIها فقط آدرس نسبی استفاده می‌کند. فونت و تصاویر محلی‌اند.

## آنچه کار می‌کند

**ویترین و صفحات عمومی**
- فید/اکسپلور RTL واکنش‌گرا، روشن/تیره، جست‌وجوی فهرست جاری، فیلتر دسته و مرتب‌سازی، استوری، پست/مودال و «بیشتر/کمتر».
- صفحات `about`، `faq`، `shipping`، `terms` و `contact` با پاورقی سراسری که ویترین و این صفحات را به هم وصل می‌کند؛ هیچ‌کدام API خصوصی صدا نمی‌زنند و ادعای خدمت فعال‌نشده ندارند.
- صفحهٔ مستقیم کالا `/p/[id]` با 404 واقعی برای کالای منتشرنشده.

**هویت، دسترسی و مدیریت**
- نشست opaque با توکن تصادفی و hash در DB، کوکی HttpOnly/SameSite، خروج و ابطال سروری، محدودیت نرخ در DB و کنترل Origin برای mutation.
- `/admin`: ورود رمز + TOTP با seed رمزگذاری‌شده، جلوگیری از بازپخش کد و هشت کد بازیابی یک‌بارمصرف. پیش از MFA هیچ دادهٔ مدیریتی ارائه نمی‌شود.
- نقش‌های پایه (مالک/پشتیبان/محتوا)، نقش سفارشی، مجوزهای عملیاتی، تعلیق پرسنل، ابطال نشست و audit؛ حساب مالک فقط با ابزار محلی ساخته می‌شود و رمز پیش‌فرض وجود ندارد.

**کاتالوگ، موجودی و عمده**
- کالا از DB خوانده می‌شود: عکس اصلی، متن، قیمت خرده، رنگ/SKU، انتشار و بایگانی؛ DTO عمومی بدون SKU، تعداد انبار یا بهای خرید.
- موجودی اولیه صفر، اصلاح مستند با دلیل/نسخه/idempotency و دفتر تغییرناپذیر.
- تعریف واقعی جین (BOM) و قیمت خصوصی نسخه‌دار برای همکار/جین مشخص با تأیید حساب مجاز دوم، انقضا و حالت استعلام.
- درخواست همکاری، بررسی مجوزدار و تنظیم اعتبار همکاری؛ تأیید همکار به‌تنهایی قیمت یا مجوز مدیریت ایجاد نمی‌کند.

**سبد، سفارش و پردازش**
- سبد سروری تکی/عمده جدا با idempotency و version؛ quote قیمت، دسترسی، BOM و موجودی تجمیعی جاری را می‌خواند.
- ثبت سفارش اولیه با snapshot تغییرناپذیر، رزرو اتمیک SKU، آزادسازی زمان‌محور، تاریخچه و لغو مشتری.
- **پنل «سفارش‌ها و رزرو»** با مجوز `order:read` / `order:manage`: فهرست و شمارش وضعیت‌ها، نمایش مبلغ ثبت‌شده و خطوط سفارش، موبایل ماسک‌شده، تأیید سفارش با کسر اتمیک موجودی، پیشروی `CONFIRMED → PREPARING → SHIPPED → COMPLETED`، دلیل الزامی و رویداد تغییرناپذیر.
- دیدگاه و پاسخ عمومی در PostgreSQL با مالکیت، moderation و idempotency.

**آزمون‌ها:** ۱۲ unit، ۱۰۱ تست یکپارچه روی PostgreSQL واقعی و ۱۴ E2E مرورگر (جزئیات در [آزمون‌ها](#آزمون‌ها)).

## ساخت امن مالک اولیه

**هیچ مالک یا رمز پیش‌فرضی در seed وجود ندارد.** این کار فقط یک بار و با دسترسی محلی مورد اعتماد انجام می‌شود؛ اگر مالک موجود باشد، ابزار او را تغییر یا reset نمی‌کند. در Bash، رمز را بدون نمایش و بدون قرار گرفتن در history/آرگومان بگیر:

```sh
read -r -s -p 'Owner password (14+ characters): ' KIYA_OWNER_PASSWORD; echo
export KIYA_OWNER_PASSWORD
npm run owner:create -- --handle kiya-owner --name 'مالک کیا'
unset KIYA_OWNER_PASSWORD
```

سپس در `/admin` وارد شو: شناسهٔ پرسنلی یا شمارهٔ موبایل ثبت‌شده، رمز، تنظیم Authenticator و تأیید TOTP. کدهای بازیابی فقط یک بار نمایش داده می‌شوند. رمز/کلید/کد بازیابی را در Git یا چت نفرست. `MFA_ENCRYPTION_KEY` باید پایدار و پشتیبان‌گیری‌شده بماند؛ تغییر خودسرانهٔ آن MFA را از کار می‌اندازد.

## آزمون‌ها

```sh
npm run db:test:create
npm run db:migrate:test
npm run db:seed -- --test
npm run prisma:validate
npm run lint
npm run typecheck
npm test            # unit
npm run test:backend # یکپارچه روی PostgreSQL واقعی (kiya_test)
npm run build
npm run test:e2e     # Playwright
npm audit --omit=dev
```

- تست بک‌اند فقط DB جداگانهٔ `kiya_test` را می‌پذیرد و دادهٔ همان DB را پاک می‌کند؛ هرگز از این نام برای دادهٔ واقعی استفاده نکن.
- E2E فقط در محیط demo محلی اجرا شود: مشتری مصنوعی ثبت می‌کند و برای بررسی MFA پرسنل موقت می‌سازد و حذف می‌کند.
- Playwright خروجی build را روی 3000 اجرا می‌کند یا سرور محلی موجود را استفاده می‌کند؛ بعد هر تغییر کد، build و restart لازم است.

## مهاجرت و محدودیت محیط

Prisma 7 با adapter استاندارد `pg`؛ Client با compiler WASM تولید می‌شود (native schema-engine از شبکهٔ sandbox قابل دانلود نیست).

**فرمان پشتیبانی‌شدهٔ migration `npm run db:migrate` است**: SQL نسخه‌دار، transaction، advisory lock و checksum با ledger مستقل `kiya_schema_migrations`. از `prisma migrate deploy/reset` روی این DB استفاده نکن. SQL شامل constraint و triggerهایی فراتر از مدل Prisma است. نسخه‌های اعمال‌شده را تغییر نده؛ migration جدید بساز (آخرین: `202610220012_order_processing`).

`npm run db:maintenance` bucketهای منقضی و نشست‌های بیش از ۳۰ روز را پاک می‌کند؛ `npm run worker:reservations` رزروهای منقضی را آزاد می‌کند. زمان‌بندی تولید با supervisor/cron انجام نشده است.

## هنوز تکمیل نشده

OTP واقعی و بازیابی مشتری، دعوت/بازیابی پرسنل، scope ریزدانه کالا/انبار، گالری و سایز، CMS صفحات عمومی و استوری، دایرکت خصوصی و تیکت، درگاه پرداخت و تطبیق مالی، هزینه/روش ارسال و مرجوعی، کد رهگیری حامل، ایمیل/پیامک/تلگرام، کیف پول/کوپن/گردونه، مالی و گزارش، و انتشار روی دامنه.

پیش از هر داده یا پرداخت واقعی لازم است: ممیزی امنیت، DB runtime با حداقل مجوز جدا از migration-owner، backup/restore، مانیتورینگ، و provider پرداخت/پیامک با آزمون‌های مالی. `APP_MODE=live` و `ALLOW_DEMO_LOGIN=false` ورود و نشست‌های demo را می‌بندند، اما به‌تنهایی سایت را آمادهٔ فروش نمی‌کنند. noindex و عدم استقرار روی دامنهٔ اصلی همچنان برقرار است.

## استقرار

پروژه یک اپ Next.js + PostgreSQL استاندارد است و به هیچ ارائه‌دهندهٔ خاصی گره نخورده: با `npm run build` و `npm run start` روی هر میزبان Node پشتیبانی می‌شود. مسیر آماده‌سازی Workers/R2/Images در پاک‌سازی 0.12 حذف شد و در تاریخچهٔ Git باقی است؛ اگر بعداً استقرار روی Cloudflare خواسته شد، از همان commit قابل بازگردانی است.

**در حساب مالک deploy نشده است.** dns، storage پایدار، backup/restore و مانیتورینگ همچنان انجام نشده‌اند.
