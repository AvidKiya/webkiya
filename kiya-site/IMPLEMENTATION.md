# وضعیت اجرای سایت مستقل کیا — ۲۰۲۶/۱۰/۲۳

**وضعیت انتشار: آمادهٔ بهره‌برداری تجاری نیست.** build موفق با استقرار موفق یا تکمیل خرید واقعی یکی نیست.

اصل قالب ۳۶فایلی دست‌نخورده است. پروژهٔ قبلی حفظ شده و کار جدید در `kiya-site/` ادامه یافته است. مرجع نیازها `backend/file/docs/14-owner-addendum.md` و نقشهٔ26 است: فقط لباس زیر، حداقل عمده یک جین، نرخ عمده خصوصی با تأیید مستقل، MFA و مجوز سرور، عدم اعتماد به مبلغ مرورگر. دامنهٔ درخواستی پاد/ویپ/سالت حذف نشده؛ دادهٔ واقعی، بررسی مقررات و پذیرش درگاه لازم است.

## آزمون‌های آخرین تغییرات

- frontend strict TypeScript و build frontend/backend: موفق.
- ۱۰۳ آزمون بک‌اند روی PostgreSQL آزمون مجزا: موفق (۹۷ هسته +۶ Cloudflare configuration). اجرای اول به علت seed نشدن دیتابیس تازه شکست خورد؛ بعد از seed صریح آزمون، هر۱۰۳ موفق شدند. دستور ریشهٔ `test:backend` اکنون آماده‌سازی/seed را هم انجام می‌دهد.
- ۱۲ unit بک‌اند +۵ آزمون جدید adapter کاتالوگ: موفق. قیمت منفی/کسری/ناامن، دادهٔ خراب، شناسهٔ تکراری، موجودی نامعتبر و نبود fallback پوشش دارند.
- آزمون مرورگر سفارشی روی dev و **خروجی ساخته‌شده**: موفق. هفت مسیر، reload، جست‌وجو/خالی، فید دیتابیس، رد دیدگاه ناشناس و حفظ متن، ورود/خروج demo واقعی، ثبت/خواندن دیدگاه پس از reload و حذف آن با API، مدیریت امن، خطای سبد ناشناس، عرض۳۹۰ و نبود خطای JavaScript.
- ۳۶ hash اصل قالب: بدون تغییر.
- npm audit آخر: backend صفر؛ frontend یک low ابزار build. ادعای audit کاملاً پاک نداریم.
- مجموعهٔ قدیمی۱۳ E2E بک‌اند و آزمون جامع تمام دکمه‌ها/فرم‌های جدید در این مرحله اجرا نشده‌اند؛ تست مرورگر فعلی اثبات خرید موفق با پرداخت یا تأیید SMS نیست.

## معیار تحویل نهایی

همهٔ ردیف‌ها باید اتصال واقعی، مجوز، مسیر شکست و آزمون مرورگر مشخص داشته باشند. اطلاعات stage/تولید و providerها از مسیر امن تنظیم شوند؛ رمز، توکن یا MFA نباید در Git یا گفتگو منتشر شود. نبود سرویس را با toast موفق یا اطلاعات نمونه پنهان نکنید. هیچ استقرار خارجی یا دریافت وجه واقعی در این مرحله انجام نشده است.

## ادامهٔ اجرا: اتصال عمده‌فروشی در همین قالب

- بخش شبیه‌سازی‌شدهٔ WholesaleView با خواندن نشست و پروندهٔ خود مشتری جایگزین شد؛ فرم فقط اطلاعاتی را می‌گیرد که واقعاً در سرور ذخیره می‌شوند. شکست POST متن فرم را از بین نمی‌برد؛ بعد از موفقیت وضعیت با GET بازخوانی می‌شود و پس از reload باقی می‌ماند.
- کاتالوگ خصوصی مستقیماً از `/api/wholesale/catalog` دریافت و اعتبارسنجی می‌شود. قیمت/ترکیب بسته در Product عمومی یا local/sessionStorage ذخیره نمی‌شود. فقط PRICED معتبر امکان افزودن دارد؛ INQUIRY قیمت صفر و دکمهٔ خرید ندارد. unit/pack/retail با BigInt و بدون گردکردن مبلغ نمایش داده می‌شوند.
- حداقل خرید همان یک جین است؛ تعداد واحد هر جین و ترکیب از BOM واقعی می‌آیند، نه فرض دوازده‌تایی یا محاسبهٔ سبد محلی. دکمه‌های قدیمی افزودن عمدهٔ محلی به صفحهٔ سروری هدایت می‌شوند.
- سبد عمده با شناسهٔ pack و requestId واقعی کار می‌کند؛ تغییر تعداد، quote، رضایت، رزرو بدون پرداخت، خواندن سفارش بعد از reload و لغو از رابط آزموده شدند. نقش محلی مجوز هیچ API نیست. انتخاب عمده به صفحهٔ خصوصی می‌رود؛ فید عمومی عمداً با نرخ همکار مخلوط نمی‌شود.
- وضعیت/قیمت در صفحهٔ فعال هر۱۵ثانیه و هنگام focus/بازگشت تازه می‌شود؛ هنگام مخفی‌شدن صفحه، قیمت‌های خصوصی و quote از DOM کنار گذاشته می‌شوند. انقضای شناخته‌شده با timer پنهان می‌شود. تعلیق مدیریتی پس از بازخوانی اعمال می‌شود، نه با ادعای push آنی؛ همهٔ عملیات حساس همان لحظه در سرور بازاعتبارسنجی می‌شوند.
- ServerCart با تغییر mode/بازوبسته‌شدن دوباره mount می‌شود؛ نتیجهٔ دیررس قبلی و quote حساب/نمای قبلی نباید در نمای تازه ظاهر شوند. پاسخ قیمت بعد از مخفی‌شدن صفحه نادیده گرفته و با بازگشت فقط سبد بی‌قیمت بازخوانی می‌شود.
- GET پرونده محدود به CUSTOMER و پروندهٔ همان نشست شد؛ cache خصوصی/no-store و Vary: Cookie دارد.

### نتایج این ادامه
- **۱۰۴ تست بک‌اند** (۹۸ هسته +۶ پیکربندی Cloudflare)، **۲۳ unit** (۱۲ بک‌اند +۵ adapter عمومی +۶ adapter خصوصی): موفق.
- مرورگر عمده روی دیتابیس مجزای kiya_test و API واقعی: منع قیمت برای ناشناس/درانتظار/رد/تعلیق/منقضی، ماندگاری درخواست، استعلام بدون قیمت فرضی، سه قیمت/BOM، افزودن یک جین، افزایش/کاهش سروری، quote، پنهان‌شدن قیمت با tab hide، رزرو/خواندن پس از reload/لغو، تعلیق با API مدیر MFA و حذف قیمت با refresh و عرض۳۹۰: موفق.
- build کامل frontend/backend و smoke مرورگر عمومی روی خروجی built: موفق؛ اصل قالب همچنان۳۶ hash یکسان دارد.
- داده‌های این آزمون کاملاً مصنوعی و فقط در دیتابیس آزمون‌اند؛ پذیرش پرداخت، SMS واقعی یا خرید تجاری انجام نشده است. مجموعهٔ قدیمی۱۳ E2E و همهٔ مسیرهای کل سایت در این ادامه اجرا نشده‌اند.
