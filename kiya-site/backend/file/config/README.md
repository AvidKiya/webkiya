# پیکربندی قابل تحویل، نه تنظیمات سرویس زنده

- brand.json: هویت قطعی عمومی کیا و مسیر لوگوها.
- catalog.json: دسته‌بندی اولیه؛ لباس معمولی خارج، لباس زیر داخل دامنه؛ DRAFT_READY یعنی نیازمند ورود محصول واقعی، نه منتظر تأیید دوبارهٔ دسته.
- wholesale-policy.example.json: پیش‌فرض تأییدشدهٔ مالک؛ یک جین در ردیف/سفارش، گام یک، بدون حداقل مبلغ اضافه. enabled=true در قرارداد یعنی ساخت این قابلیت الزامی است، نه اینکه اپ/درگاه اکنون فعال است.
- integrations.json: وضعیت‌های صادقانهٔ UNCONFIGURED/UNVERIFIED؛ هرگز از روی config حکم اتصال موفق نده.

سازنده این داده‌ها را با schema نسخه‌دار به seed یا تنظیمات اپ تبدیل کند؛ JSON به‌تنهایی backend نیست. فعال‌سازی runtime و قیمت واقعی، PackDefinition و تست نیاز دارند. تنظیم FEATURE_WHOLESALE=false در env نمونه مانع فعال‌سازی تصادفی پیش از setup می‌شود؛ پس از تکمیل setup فعال می‌شود. حداقل تعداد به خریدار تحمیل نشود مگر همان یک جین مصوب.
