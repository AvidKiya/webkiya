# سایت مستقل کیا — شروع دوباره از خود قالب مالک

این پروژهٔ جدا داخل `kiya-site/` است. پروژهٔ قبلی ریشهٔ مخزن پاک/جابه‌جا نشده است.

## تازه: تلگرام و کارت‌به‌کارت

ورود مشتری با لینک یک‌بارمصرفِ متصل به مرورگر و تأیید خصوصی تلگرام، تنظیمات امن OWNER/MFA در `/admin/settings` و ثبت/بررسی خصوصی رسید در `/admin/payments` اضافه شد. [راهنمای دقیق فعال‌سازی، worker، وضعیت تست‌ها و محدودیت‌های واقعی](../file/docs/33-telegram-and-card-transfer.md). ذخیرهٔ کلید به معنی اتصال سالم نیست؛ در این تحویل توکن تازه/تراکنش واقعی/استقرار تولید انجام نشده است. ورود تلگرام، حساب مدیر یا شمارهٔ تأییدشدهٔ ساختگی ایجاد نمی‌کند.

## پوشه‌ها
- `template-original/`: کپی دقیق ۳۶ فایل قالب ارسالی؛ مرجع ثابت طراحی، نه برنامهٔ تولید. hashها در `template-manifest.json` هستند.
- `frontend/`: همان اجزا و چیدمان قالب، با Vite/React؛ مسیر توسعهٔ رابط جدید. فونت محلی، فایل‌های لوگوی جاافتاده، مسیریابی hash و جست‌وجوی فید اصلاح شدند.
- `backend/`: کپی مستقل هستهٔ Next/PostgreSQL فعلی، migrationها، تست‌ها، storage، مجوز و MFA و **تمام بستهٔ توضیحات/نقشه‌های قبلی در `backend/file/`**. دیتابیس محلی این پروژه port55433 دارد و با سایت قبلی مشترک نیست.
- `scripts/`: اجرای دو سرویس و بررسی دست‌نخوردن اصل قالب.

## اجرای مستقل
Node22 لازم است. در همین پوشه:
```sh
npm run install:all
npm --prefix backend run db:local
```
پس از آماده‌شدن دیتابیس، در ترمینال دوم:
```sh
npm --prefix backend run db:migrate
npm --prefix backend run db:seed
npm run dev
```
رابط جدید روی3100 و بک‌اند روی3101 اجرا می‌شود. مرورگر API را با مسیر نسبی `/api` از proxy رابط می‌گیرد؛ آدرس localhost بک‌اند به مرورگر خارجی داده نمی‌شود. secretها در فایل ignored خود backend هستند؛ فایل env ریشه را کپی نکنید.

```sh
npm run test:template
npm run build
node frontend/tests/browser.mjs
```
آزمون مرورگر به دو سرویس روشن و نصب dependencyهای backend نیاز دارد.

## وضعیت اتصال‌ها — ۲۰۲۶/۱۰/۲۳

فید اصلی همان قالب اکنون به `/api/catalog` وصل است؛ صفحهٔ جداگانهٔ کاتالوگ حذف شده است. دیدگاه‌ها در PostgreSQL ثبت/خوانده می‌شوند و خطای ارسال متن فرم را پاک نمی‌کند. حساب مشتری نشست واقعی، خروج و سفارش‌های سرور را می‌خواند. سبد از API دریافت می‌شود؛ تغییر تعداد/حذف با version، quote و رزرو موقت بدون پرداخت با fingerprint و requestId انجام می‌شوند. قیمت قابل پرداخت از مرورگر فرستاده نمی‌شود. درخواست و وضعیت همکاری، کاتالوگ اختصاصی تأییدشده با BOM و سه قیمت، سبد عمدهٔ واقعی و رزرو از یک جین متصل‌اند؛ نرخ استعلامی قابل خرید نیست. خودتأییدی و نقش‌های آزمایشی مجوز نمی‌دهند. لینک مدیریت به `/admin` امن بک‌اند می‌رود، نه مدیریت ساختگی مرورگر.

ورود آزمایشی فقط در پیکربندی محلی مجاز است و تأیید شماره محسوب نمی‌شود. کالاهای seed نمونه‌اند و سرور فروش آن‌ها را رد می‌کند؛ این داده‌ها اثبات تکمیل خرید واقعی نیستند. محتوای نمونهٔ مجله/دایرکت/فعالیت فروش و سابقه/پول ساختگی از نمای عمومی حذف شده‌اند؛ آن بخش‌ها هنوز عملیاتی نیستند. لایک و ذخیرهٔ فعلی صرفاً تعامل مرورگرند.

**این نسخه هنوز آمادهٔ بهره‌برداری تجاری نیست.** ورود مشتری با SMS، پرداخت و callback، آدرس/ارسال/مالیات، اتصال مدیریت با ظاهر قالب، CMS و پیام‌رسان و انتشار عملیاتی تکمیل نشده‌اند. اکانت مالک در دیتابیس فعلی ایجاد نشده و Neon/Cloudflare/دامنه به‌صورت واقعی مستقر نشده‌اند. جزئیات دقیق در `IMPLEMENTATION.md` است.

## آزمون و پیش‌نمایش خروجی build

```sh
npm run test:unit
npm run test:backend
npm run test:template
npm run build
npm run preview:build
# در ترمینال جدا:
node frontend/tests/browser.mjs
```

`test:backend` دیتابیس **آزمون مجزا** را می‌سازد، migration و seed آزمون را اجرا می‌کند؛ نیازمند PostgreSQL محلی روشن است. آزمون‌های آن فقط با تنظیم TEST_DATABASE_URL مجازند. تست مرورگر نیازمند حالت محلی demo و ورود آزمایشی صریحاً مجاز است؛ هرگز روی production اجرا نشود. این تست یک دیدگاه مصنوعی می‌سازد و از API حذف می‌کند؛ tombstone/audit و کاربر demo ممکن است در دیتابیس محلی بماند.

`preview:build` دو خروجی ساخته‌شده را با proxy مشترک `/api`، `/admin` و `/_next` روی3100/3101 برای **بازبینی محلی** اجرا می‌کند. این دستور جای استقرار تولید، TLS، backup، worker و تنظیم سرویس‌ها نیست. قبل از اجرا سرویس‌های dev روی همین پورت‌ها را متوقف کنید.

## آزمون یکپارچهٔ عمده‌فروشی — فقط دیتابیس آزمون

پس از روشن‌کردن PostgreSQL محلی، از همین پوشه:

```sh
npm run test:wholesale:prepare
npm run dev:ui-test
# در ترمینال جدا، پس از آماده‌شدن هر دو سرویس:
npm run test:wholesale:browser
```

آماده‌سازی، ۱۰۴ تست بک‌اند را اجرا و فقط با گزینهٔ صریح fixture مصنوعی مرورگر می‌سازد. سرویس تست به **kiya_test روی localhost** محدود است و اتصال به دیتابیس توسعه/تولید را رد می‌کند. رابط3110 از proxy به بک‌اند3111 می‌رود؛ پیش‌نمایش اصلی3100/3101 را عوض نمی‌کند. آزمون اطلاعات همکاری و سبد/رزرو را تغییر می‌دهد و حساب تست را تعلیق می‌کند؛ برای اجرای مجدد ابتدا prepare را تکرار کنید. هم‌زمان مجموعهٔ بک‌اند دیگری روی همین دیتابیس اجرا نشود.

فایل ignored `backend/.data/wholesale-ui-fixture.json` حاوی نشست‌های موقتِ **حساب‌های مصنوعی تست** است؛ آن را منتشر نکنید. پس از توقف سرویس تست حذفش کنید. هیچ fixture/توکن تستی نباید وارد دیتابیس واقعی شود. کاربر demo در محیط live مجوز خرید/قیمت ندارد. کلید خصوصی، رمز مالک و MFA برای نمایش قیمت تست افشا یا غیرفعال نمی‌شوند.

قیمت همکار فقط در بخش خصوصی نگه داشته می‌شود، نه در مدل عمومی کالا. ادغام این دو مدل یا ذخیرهٔ نرخ خصوصی در مرورگر مجاز نیست. اعتبار در هر محاسبه/رزرو دوباره در سرور بررسی می‌شود؛ UI جای کنترل مجوز نیست.
