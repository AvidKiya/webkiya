## بسته‌ای که ارسال می‌شود
پوشهٔ `file/` را کامل با حفظ نام پوشه‌ها بفرست: README، docs، preview home، preview panel، screenshot home، screenshot panel و scripts. اسناد اصلاحیه را جدا از پوشه نفرست؛ بدون تقدم اسناد، سازنده ممکن است تناقض‌های قدیمی را اجرا کند. نیازی به ارسال .git، token، دادهٔ مشتری یا node_modules نیست.

تو تیم طراحی محصول، معماری، پیاده‌سازی و QA پروژهٔ «کیا ویترین» هستی.
تمام پوشهٔ تحویل را ابتدا inventory کن. این یک بستهٔ سند و HTML نمایشی است، نه اپ موجود.
ابتدا README و docs/00-execution-contract.md و سپس 09 تا 13 را کامل بخوان؛ بعد 01 تا 08، decisions و backlog و DESIGNها و نمونه‌های بصری را بررسی کن.

محصول: فروشگاه اجتماعی فارسی RTL با هویت مستقل، فید و پست‌محصول، ظاهر متناسب با دسکتاپ/موبایل، خرید دقیق و امن، پنل حرفه‌ای و نقش/Scope قابل تنظیم.
فقط V1 را در اولین قرارداد بساز؛ V1.1 و V2/V3 را حذف نکن ولی خارج از محدوده و خاموش نگه دار.
اول خروجی بده: خلاصهٔ نیازها، ابهامات مسدودکننده، route map، ERD و برنامهٔ فازبندی با acceptance IDها. فرض جدید را ADR کن و موضوع حساس مالی/حقوقی را حدس نزن.
نسخه‌های سازگار و پشتیبانی‌شدهٔ stack را انتخاب و pin کن؛ schema داخل سند ۰۶ را مستقیم runnable فرض نکن. تمام مدل‌های ضروری سند ۱۱، قیود SQL، migration، seed جعلی و تست validate لازم‌اند.
پیاده‌سازی را مرحله‌ای انجام بده:
A) طراحی سیستم، پوستهٔ RTL و routes و UI با دادهٔ demo صریح؛
B) دیتابیس، session/OTP/MFA، permission catalog و نقش/Scope و audit؛
C) محصول، فید، پست deep-link، بیشتر/کمتر و کامنت واقعی؛
D) سبد، quote، رزرو اتمیک، پرداخت idempotent، سفارش/return/refund؛
E) پنل عملیاتی و گزارش‌های قابل تطبیق؛
F) سخت‌سازی، تست، deploy و راهنمای عملیات.
هیچ مرحله با toast، alert یا localStorage به‌جای backend تمام‌شده محسوب نمی‌شود.
مجوزها روی سرور، مالکیت هر resource، DTOهای بدون PII و deny-by-default الزامی‌اند. فقط OWNER نقش تخصیص می‌دهد. دادهٔ مالی server-authoritative و Decimal تومان است.
کامنت باید پس از reload باقی بماند؛ پاسخ یک‌سطحی، retry بدون تکرار، moderation و نشان خرید مشتق از سفارش واقعی. «بیشتر» با keyboard و صفحه‌خوان کار کند.
همهٔ صفحات loading/empty/error/partial/offline داشته باشند. محصول مستقل هم همان هویت اجتماعی را حفظ کند، نه کپی برندهای دیگر.

تحویل: کد کامل، env.example بدون secret، migrations، seeds، API contract، CI، unit/integration/e2e، docker/deploy/rollback/restore runbook و گزارش traceability. هیچ ادعای production-ready بدون شواهد سند ۱۲ نکن.

## مهارت‌ها / Skillهایی که سازنده باید پوشش دهد
اگر منظور از «اسکیل» مهارت ایجنت است: UX فارسی و RTL، طراحی responsive، accessibility، Next/TS، Postgres transactions، Prisma migrations، امنیت session/RBAC/ABAC، payment adapter، صف و idempotency، testing/observability و عملیات. داشتن نام یک ابزار یا نصب یک skill جای آزمون عملی را نمی‌گیرد. اگر منظور مقیاس است، برنامهٔ زیر ملاک پیشنهادی است.

## مقیاس و عملیات (فرض قابل اندازه‌گیری)
- برای شروع monolith ماژولار + worker مستقل؛ microservice و sharding پیش از دادهٔ بار واقعی لازم نیست.
- load-test پیشنهادی staging: ۱۰۰ خوانندهٔ هم‌زمان فید و ۲۰ checkout رقابتی آخرین واحد. گزارش RPS، p50/p95/p99، خطا، CPU/RAM، pool و lock wait لازم است؛ «بازدید روزانه» ظرفیت تضمینی نمی‌سازد.
- هدف اولیهٔ پیشنهادی API خواندنی cache-hit p95<500ms و نوشتن عادی <1s بدون زمان provider؛ ابتدا baseline بگیر. فشار pool/queue/latency پایدار → index و cache/worker capacity، سپس replica برای گزارش، نه بلافاصله sharding.
- هشدارها: verify ناموفق، PAYMENT_REVIEW، queue lag، outbox تکرارشونده، stock invariant، خطای 5xx، شکست SMS، فضای DB و بکاپ؛ log با requestId و traceId بدون PII.
- هدف پیشنهادی بازیابی RPO≤۱۵ دقیقه، RTO≤۴ ساعت تنها با WAL/PITR و restore drill قابل ادعاست؛ full backup روزانه به‌تنهایی این RPO را تأمین نمی‌کند. قابلیت provider و هزینه را پیش از تعهد تأیید کن.
- incident پرداخت: ارسال سفارش را freeze، وضعیت provider را reconcile، از retry با کلید جدید خودداری، مالک و مالی را مطلع و timeline بدون secret ثبت کن.
- deploy: backup و migration plan → staging tests → deploy سازگار با schema → smoke → پایش. rollback کد لزوماً rollback داده نیست؛ migration مخرب با expand/contract و backup تأییدشده.
- نگهداری داده: session/OTP منقضی پاک‌سازی زمان‌بندی‌شده؛ حذف حساب = حذف/ناشناس‌سازی غیرضروری‌ها و تفکیک رکوردهای مالی با دسترسی محدود طبق مهلت قانونی تأییدشده. شماره و آدرس سند مالی را کورکورانه هش نکن. مدت دقیق نگهداری و رضایت بازاریابی تصمیم مالک/مشاور است.

## وضعیت تحویل فعلی
بسته برای **ارسال جهت برآورد، طراحی و آغاز ساخت با فرض‌های ثبت‌شده** مرتب شده است. نرم‌افزار، deployment و تست‌های runtime هنوز ساخته/اجرا نشده‌اند. در فایل ۰۹ شکاف‌ها و در ۱۲ معیار بستن آن‌ها مشخص است.
