# نقشهٔ تکمیل کیا — چه ساخته شده، چه مانده و چه نیاز به بررسی دارد؟

نسخه0.10.0 · 2026-10-22 · شاخه `arena/f6a09f64-webkiya`

**مسیر قابل مشاهده داخل اپ: `/progress`**. لینک آن در پنل مدیریت و هدر دسکتاپ فروشگاه هست. این نقشه snapshot نسخه‌دار توسعه است، نه درصد تخمینی، گزارش زندهٔ فروش یا ادعای تکمیل FULL. حساب واقعی مدیر کل دست‌نخورده است؛ MFA و رمز شخصی در Git نیستند.

## ۱. آنچه الان قابل استفاده و تست‌شده است

- ویترین اجتماعی با قالب انتخابی مالک: RTL/موبایل/سه‌ستونهٔ دسکتاپ، هدر/ناوبری/پست، پروفایل برند، اکسپلور، بازشدن پست، جست‌وجوی فهرست جاری، بیشتر/کمتر و تم؛ سبد سروری و نمونهٔ محلی جدا.
- PostgreSQL، نشست سروری، MFA کارکنان، مدیر کل و تیم، نقش سفارشی، مجوزهای عملیاتی، تعلیق/ابطال نشست و audit.
- کاتالوگ از دیتابیس؛ ثبت عکس اصلی، متن و قیمت خرده، رنگ/SKU، انتشار و بایگانی.
- موجودی اولیه صفر، اصلاح مستند، version/row-lock/idempotency و دفتر تغییرناپذیر موجودی.
- دیدگاه و پاسخ عمومی، کنترل مالکیت و moderation؛ این‌ها دایرکت خصوصی نیستند.
- درخواست همکاری و بررسی مجوزدار؛ تأیید همکار به‌تنهایی قیمت عمده یا مجوز مدیریت ایجاد نمی‌کند.
- تعریف واقعی جین با ترکیب SKU، تعداد محاسبه‌شده، پیش‌نویس/فعال/بایگانی و حفاظت در برابر تغییر تعریف فعال. به قیمت خصوصیِ همکار مشخص متصل شد؛ به رزرو و سفارش اولیهٔ عمده متصل شد؛ پرداخت و انجام سفارش هنوز نیست.

«تست‌شده» محدود به همین رفتارها و محیط محلی است، نه تضمین امنیت/ظرفیت تولید. مقدار مالی یا موجودی واقعی از روی fixture حدس زده نشده است.

- **تازه در0.7:** قیمت خصوصی نسخه‌دار برای همکار/جین مشخص، تأیید حساب مجاز دوم، انقضای قیمت و همکاری، حالت استعلام و نمایش سه قیمت فقط برای همان حساب.

**تازه در0.9:** [رزرو و سفارش اولیه](30-initial-orders.md) با snapshot و انقضا/لغو؛ بدون پرداخت یا مجوز ارسال.

**تازه در0.10:** [قالب انتخابی مالک](31-selected-template.md) با حفظ نسخهٔ اصلی و اتصال اجزای رابط به هستهٔ سروری. ظاهر جدید، معادل تکمیل همهٔ ماژول‌های نمایشی قالب نیست.

## ۲. مسیر اصلی تا فروش واقعی

**کالا و موجودی → تعریف جین → قیمت خصوصی عمده → سبد/quote سروری → رزرو SKU → سفارش → پرداخت/ارسال/مرجوعی → ممیزی و انتشار.**

| گام | وضعیت | شرط خروج / کاری که باید تکمیل شود |
|---|---|---|
| کالا و موجودی پایه | پیاده و تست شده | دادهٔ واقعی را مالک در پنل وارد و تأیید کند؛ گالری/سایز/pagination توسعهٔ بعدی‌اند. |
| تعریف واقعی جین | هستهٔ تعریف پیاده؛ فروش عمده ناقص | ترکیب واقعی ثبت شود؛ اتصال اختصاصی قیمت پایه ساخته شده، quote و سبد پایه ساخته شده؛ رزرو/سفارش اولیه ساخته شد؛ انجام سفارش/پرداخت باقی است. یک جین کافی است؛ تعداد داخل آن الزاماً۱۲نیست. |
| قیمت خصوصی عمده | تخصیص مستقیم و نمایش خصوصی تست شده؛ محدودهٔ کامل ناقص | لیست گروهی/عمومی، tier، قیمت متفاوت اجزا و اتصال به سفارش/پرداخت باقی است. |
| سبد و quote سروری | پایه پیاده و تست‌شده | /basket با retail/wholesale جدا، قیمت/BOM/اعتبار جاری، idempotency/version و stock تجمیعی؛ quote تنها رزرو نمی‌کند؛ ثبت صریح سفارش اولیه snapshot و رزرو می‌سازد. مبلغ قابل پرداخت تعیین نشده است. |
| رزرو و سفارش | هستهٔ اولیه پیاده و تست‌شده | رزرو اتمیک/انقضا، idempotent place، snapshot و لغو؛ پنل پردازش، آدرس، مالیات/ارسال، پرداخت و وضعیت‌های بعدی باقی است. |
| درگاه و OTP | وابسته به ارائه‌دهنده؛ اتصال نشده | adapter واقعی، کلید امن، sandbox و آزمون verify/webhook/خطا؛ ورود آزمایشی جای OTP نیست. |
| ارسال و مرجوعی | نیاز به قواعد واقعی و پیاده‌سازی | روش‌ها/هزینه/وزن/شهر/زمان، ضمانت و متن حقوقی تأییدشده. |
| تولید و دامنه | انجام نشده | runtime کم‌اختیار، backup/restore، storage، پایش، ممیزی، اجازهٔ deploy/DNS و smoke. |

**اولویت بعدی کدنویسی:** مدیریت و پردازش سفارش اولیه با RBAC، آدرس و مدل سیاست ارسال/مالیات؛ سپس پرداخت sandbox با revalidation. برای ساخت مدل و تست آن نیازی به کلید پرداخت نیست؛ برای فعال‌سازی مالی داده و تأیید واقعی لازم است.

## ۴. چه چیزهایی از مالک لازم می‌شود؟

### قطعی و بدون نیاز به پرسش تکراری
- کیا/KIYA، هویت بنفش/طلایی، دامنهٔ هدف kiyaco24.ir.
- لباس معمولی نداریم؛ لباس زیر داریم.
- حداقل عمده یک جین، بدون کف مبلغ اضافه؛ واحدهای هر جین از ترکیب واقعی کالا.
- عمده فقط برای حساب تأییدشده؛ همکار نقش ادمین نیست.

### دادهٔ عملیاتی لازم، نه مانع ساخت ابزار
- عکس/مشخصات/رنگ/سایز، شمارش موجودی واقعی و ترکیب هر بسته.
- قیمت واقعی خرده و عمده؛ آیا یک لیست عمومی همکار کافی است یا لیست اختصاصی/گروهی لازم است؟ ابزار می‌تواند مدل صریح و نسخه‌دار داشته باشد، اما قیمت حدسی وارد نمی‌شود.
- بسته‌های چندسایز: نام و ابعاد SKU واقعی، راهنمای سایز و قوانین ترکیب؛ فعلاً مدل مستقل سایز ساخته نشده است.

### بررسی/تصمیم قبل فعال‌سازی
- هزینه و شهرهای ارسال، زمان آماده‌سازی، ضمانت، مرجوعی، مالیات و متن حقوقی.
- سیاست تأیید مستقل عملیات حساس مالی، نقش‌های مالی و سطح اختیارات.
- انتخاب سرویس OTP/درگاه/زیرساخت و اجازهٔ اتصال، هزینه و deployment. **کلید، رمز و token را در چت یا Git نفرستید**؛ فقط در تنظیم امن محیط وارد شوند.
- ممیزی امنیت/حریم خصوصی، حقوق تصاویر و محتوای مشروط، نسخهٔ پشتیبان و مسئول عملیات.

## ۵. مسیر استفاده همین حالا

- `/progress`: همین نقشه در رابط سایت؛ بدون درخواست API مدیریت یا نمایش PII.
- `/`: ویترین فعلی؛ سفارش/پرداخت واقعی خاموش.
- `/admin/preview`: مرور ظاهر مدیریت، فقط‌خواندنی و بدون اختیار.
- `/admin`: رمز و MFA شخصی → «کاتالوگ» → پروندهٔ کالا → «تعریف واقعی جین و ترکیب رنگ‌ها».
- جین را وقتی کالا DRAFT است بسازید؛ سپس کالا را منتشر و تعریف جین را فعال کنید. فعال‌سازی تعریف، فروش/رزرو یا تغییر stock ایجاد نمی‌کند.

## ۶. شواهد و گیت تحویل

این مرحله: ۱۲ unit، ۶۷ integration PostgreSQL و۱۰ E2E؛ تست‌های تازه BOM، نسخه/رقابت، FK یک‌محصول، حفاظت تعریف فعال، مجوز و نقشهٔ عمومی را پوشش می‌دهند. نتیجهٔ دقیق build/lint/audit/validation در [گزارش۲۸](28-private-wholesale-prices.md) ثبت می‌شود. بررسی مرورگر فرم باز در عرض۳۶۰تا۱۴۴۰ انجام شده است؛ این مساوی ممیزی کامل WCAG یا بارسنجی نیست.

هر ادامه باید همین نقشه، گزارش، tests، migration و وضعیت GitHub را به‌روز کند. تکمیل FULL فقط وقتی F01..F16 و گیت‌های عملیاتی واقعاً گذرانده شوند، نه با عوض‌کردن برچسب به «کامل».
