# ۰۷ — پرامپت‌پک (Prompt Pack) برای ساخت با ایجنت هوش مصنوعی

> **به‌روزرسانی مالک:** [اصلاحیهٔ کیا](14-owner-addendum.md) و اسناد ۱۵ تا ۱۸ مقدم‌اند: برند KIYA، بنفش/طلایی، عمده در هسته و هدف نهایی FULL. نام‌ها/فازهای قبلی در این فایل تاریخی‌اند.

> **اصلاحیهٔ اجرایی 2026-10-22:** [قرارداد مرجع](00-execution-contract.md) و اسناد ۰۹ تا ۱۳ بر جزئیات متعارض این سند مقدم‌اند. این فایل مشخصات است، نه اثبات پیاده‌سازی.

> این فایل را می‌توانی مستقیم به Cursor / Claude Code / Codex / Copilot Workspace / Windsurf بدهی.
> **قاعدهٔ استفاده:** فایل `AGENTS.md` را در ریشهٔ ریپو بساز، سپس پرامپت مادر را یک بار در ابتدای جلسه/چت بده، و بعد **فاز‌به‌فاز** پرامپت‌ها را اجرا کن. هر فاز را کامل تست و commit کن قبل از فاز بعد.
> نام پروژه: `vitrin` — تاریخ مرجع اسناد: ۱۴۰۵/مهر (2026-10)

---

## ۰. دستورالعمل استفاده (۶ نکته)

1. **یک فاز = یک شاخهٔ گیت.** هیچ‌وقت چند فاز را هم‌زمان به ایجنت نده.
2. هر پرامپت با عبارت «**طبق اسناد موجود در `docs/`**» شروع می‌شود تا ایجنت سند را مرجع بگیرد.
3. اگر ایجنت چیزی را حدس زد، از او بخواه **در `docs/decisions.md` ثبت کند** (ADR کوتاه).
4. بعد از هر فاز این چهار دستور را اجرا کن: `pnpm lint && pnpm typecheck && pnpm test && pnpm build`.
5. اگر خروجی از محدودهٔ اسکوپ فاز بیرون زد، بگو: «فقط اسکوپ همین فاز؛باقی را در `docs/backlog.md` یادداشت کن».
6. UI را هرگز بدون **حالت‌های Loading/Empty/Error** قبول نکن.

## ۱. `AGENTS.md` — قوانین دائمی پروژه (این را در ریشهٔ ریپو بساز)

```markdown
# AGENTS.md — Vitrin Social Commerce

## زبان و منطقه
- UI: فارسی (fa-IR)، RTL، ارقام فارسی، تقویم جلالی برای نمایش.
- کد: TypeScript ، نام‌گذاری انگلیسی، کامنت‌های توضیحی فارسی در بخش‌های دامنه‌ای پیچیده.

## استک (قابل مذاکره نیست مگر با ADR)
- Next.js 15 (App Router, RSC, Server Actions), TypeScript strict, React 19
- Tailwind CSS v4 + CSS variables (توکن‌های docs/02-design-system.md)
- Prisma + PostgreSQL 16
- Zod برای همهٔ ورودی‌ها (سرور و کلاینت)
- Auth: session کوکی HttpOnly + OTP موبایل (خریدار) و رمز+2FA (کارکنان)
- State: TanStack Query برای داده‌های async، Zustand فقط برای UI محلی
- Test: Vitest (unit), Playwright (e2e), Testing Library
- Lint/Format: ESLint + Prettier + `tsc --noEmit`
- Storage: S3-compatible (R2) + sharp برای تبدیل

## معماری پوشه‌ها
src/
├─ app/
│  ├─ (store)/ …          # فروشگاه: /, /explore, /p/[id], /product/[slug], /cart, /checkout
│  ├─ admin/              # پنل (layout جدا)
│  ├─ api/                # Route Handlers عمومی و webhooks
│  └─ auth/
├─ components/
│  ├─ ui/                 # primitives (Button, Input, Sheet, Modal, Toast…)
│  ├─ store/              # PostCard, CommentList, StoryRing, CartSheet
│  ├─ admin/              # DataTable, StatCard, PermissionGate
│  └─ shared/
├─ server/
│  ├─ actions/            # Server Actions با requirePermission
│  ├─ services/           # منطق دامنه (order, inventory, comment, campaign)
│  ├─ guards/             # requirePermission, scopedWhere, audit
│  └─ jobs/               # worker: کمپین، رزرو موجودی، اعلان
├─ lib/                   # utils, permissions, formatters (jalali, currency)
├─ prisma/
└─ styles/

## قواعد غیرقابل‌نقض کدنویسی
1. هر mutation ابتدا احراز هویت/مالکیت مشتری یا requirePermission و Scope کارکنان، سپس اعتبارسنجی و سرویس دامنه؛ تغییر حساس و audit در همان تراکنش. خواندن عمومی نیاز به مجوز اداری ندارد.
2. هر مبلغ: `Decimal` سمت سرور؛ فرمت نمایش با `formatToman()`؛ هرگز محاسبهٔ مالی در کلاینت.
3. هر کامپوننت عمومی باید props تایپ‌شده، `aria-*` کاربردی و حالت‌های loading/disabled داشته باشد.
4. بدون `any`. بدون `@ts-ignore` بدون توضیح دلیل.
5. تصاویر: `next/image` + `sizes` + `placeholder="blur"`.
6. هیچ fetch سمت کلاینت به دامنهٔ خارجی بدون دلیل مستند؛ SEO نیاز به RSC دارد.
7. خطاها با `Result` type یا throw کنترل‌شده؛ پیام‌های کاربر پسند فارسی، پیام فنی در لاگ.
8. هر ویژگی کاربرپسند = یک رویداد آنالیتیکس (`track('add_to_cart', {...})`).
9. تست: برای سرویس‌های دامنه حداقل یک unit test؛ برای مسیرهای حیاتی (خرید، کامنت، RBAC) e2e.
10. اگر تغییری در اسکیمای Prisma دادی، migration + seed + به‌روزرسانی docs/06 را با هم انجام بده.

## Definition of Done (هر کار)
- [ ] کد + تست + lint + typecheck سبز
- [ ] حالت‌های Loading/Empty/Error/Offline
- [ ] موبایل و دسکتاپ بررسی شده
- [ ] دسترس‌پذیری: کیبورد + aria + کنتراست
- [ ] مجوزها اعمال و در AuditLog ثبت شده (اگر نوشتاری است)
- [ ] مستند کوتاه در docs/decisions.md
```

```

و انضباط تراکنشی (دیجی‌کالا). یک پنل مدیریت حرفه‌ای با نقش‌بندی و کنترل دسترسی دقیق هم بخشی از محصول است.

قبل از شروع، این فایل‌ها را کامل بخوان و مرجع بگیر:

اصول کاری تو:
- فقط اسکوپ همان فازی که می‌دهم را پیاده کن. کار خارج از اسکوپ را در docs/backlog.md بنویس.
- قبل از کدنویسی، یک برنامهٔ کوتاه (۵ تا ۱۰ بولت) و فهرست فایل‌هایی که می‌سازی/تغییر می‌دهی را بده.
- بعد کد کامل بنویس (نه خلاصه، نه «... بقیه مشابه»). هیچ فایل نیمه‌کاره نگذار.
- همه‌جا TypeScript strict، Zod، و الگوهای موجود پروژه را رعایت کن.
- برای هر صفحه/کامپوننت: حالت‌های Loading/Empty/Error را هم بساز.
- در پایان هر فاز: دستورهای تستی که باید اجرا کنم + چک‌لیست پذیرش + آنچه باقی مانده را بنویس.
- اگر تصمیم معماری گرفتی، ADR کوتاه در docs/decisions.md اضافه کن.
- فارسی‌بودن UI و RTL و ارقام فارسی و تاریخ جلالی غیرقابل‌مذاکره است.

اکنون آماده‌ام؛ منتظر پرامپت فاز اول بمان (یا اگر فاز اول را در ادامه دادم، همان را اجرا کن).
```

   پاسخ سریع، تخصیص، برچسب، SLA رنگی، کارت‌های غنی داخل چت، رضایت‌سنجی.
