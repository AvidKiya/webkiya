# ۲۳ — دیدن مدیریت و پیش‌نویس واقعی کالا

تاریخ: 2026-10-22 · نسخه0.3.0 · همان شاخه arena/f6a09f64-webkiya.

در پاسخ به درخواست «ادامه بده و بخش مدیریت هم می‌خوام ببینم»:

## نمایش بدون دورزدن احراز هویت
`/admin/preview` از همان component و CSS مدیریت استفاده می‌کند، ولی با دادهٔ محلیِ مشخصاً نمونه. هر شش tab قابل مرور است؛ فرم‌های تغییر اطلاعات وجود ندارند، API خصوصی فراخوانی نمی‌شود و cookie/حساب مدیر ساخته نمی‌شود. banner دائمی می‌گوید این نما فقط‌خواندنی و اعداد غیرواقعی‌اند. لینک آن بالای فروشگاه، در حساب من و صفحهٔ ورود پرسنل است. `/admin` و APIهای آن همچنان رمز/MFA/RBAC لازم دارند. state نمایشی در مرورگر هیچ authority سروری ندارد.

## ادامهٔ عملیاتی مدیریت کالا
migration003 ستون‌های Product.version/updatedAt و مجوز product:write فقط برای OWNER را اضافه می‌کند. SQLهای قبلی تغییر نکرده‌اند. API POST /api/admin/products و PATCH /api/admin/products/[id] نام و قیمت integer-string را فقط برای DRAFT می‌پذیرند؛ status، نقش یا قیمت اعشاری از client پذیرفته نمی‌شود. ویرایش با lock/version، audit در همان transaction و پاسخ409 برای درخواست stale است. کالای منتشرشده از این مسیر تغییر نمی‌کند. DTO قیمت به‌صورت string است.

پنل واقعی برای صاحب مجوز، فرم ساخت و ویرایش پیش‌نویس دارد؛ نقش‌های CONTENT/SUPPORT پایه فقط خواندنی باقی‌اند. هنوز ایجاد نقش سفارشی یا انتشار محصول در UI ساخته نشده است. فید فعلی استاتیک و نمونه است؛ پیش‌نویس‌ها خودکار به فید وارد نمی‌شوند. واریانت، پک/BOM، تصویر تأییدشده، موجودی، قیمت خصوصی، quote/payment هنوز ساخته نشده‌اند. POST ساخت پیش‌نویس هنوز کلید idempotency ندارد؛ برای retry بعد از قطع شبکه ابتدا فهرست بررسی شود.

## شواهد
- ۲۳ تست بک‌اند واقعی PostgreSQL: چهار مورد تازه برای writer/MFA، مقدار پول و payload انتشار، رقابت optimistic lock و جلوگیری از تغییر قیمت کالای منتشرشده.
- ۷ E2E: آزمون تازهٔ preview هر شش tab و صفر API call/بدون session، به‌علاوه توسعهٔ آزمون staff برای ساخت/ویرایش پیش‌نویس و ماندگاری بعد reload با نقش محدود موقت و پاک‌سازی fixture.
- ۱۰ unit و lint/typecheck/build؛ محدودیت امنیت و providerهای گزارش۲۲ همچنان پابرجاست.
- workflow مرحلهٔ قبل، commit bda7b98، با PostgreSQL16 موفق شد: https://github.com/AvidKiya/webkiya/actions/runs/39766351427 . این شاهد برای همان commit است؛ نتیجهٔ تغییرات جدید جداگانه بررسی شود.
