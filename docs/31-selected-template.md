# گزارش۳۱ — قالب انتخابی مالک، روی سایت سروری موجود

2026-10-22 · نسخه0.10.0 · شاخه arena/f6a09f64-webkiya. درخواست مالک: قالبی که در GitHub گذاشته مبنا باشد و همان سایت قبلی با تمام محدودهٔ FULL توسعه یابد، نه ساخت یک نمونهٔ جدا یا حذف کار قبلی.

## شناسایی و ادغام

قالب در main، commit `297053647484a46aea54bc35967cebd78a583782` با عنوان «قالب مورد پسندم» و پوشهٔ «کیایی که دوسش داشتم» بود. ۳۶فایل آن بدون تغییر حفظ و main در شاخهٔ جاری ادغام شد. داده، migrationهای001..011، حساب واقعی مدیر، MFA، RBAC و سرویس‌های موجود جایگزین نشدند. نصب و اجرا همچنان از ریشه با Next/Prisma/PostgreSQL است، نه از package مستقل Vite قالب.

قالب اصلی frontend نمونه است: StoreContext محلی، جابه‌جایی persona، قیمت‌های نمونه، سفارش/پرداخت شبیه‌سازی، پیام و فعالیت نمونه دارد؛ Logo آن به assetهایی اشاره دارد که در آن commit موجود نیستند. انتقال مستقیم تمام آن به برنامهٔ مالی باعث دورزدن احراز، قیمت خصوصی و جعل موفقیت می‌شد. اجزای انتخابی برای route واقعی و APIهای موجود اقتباس شدند؛ لوگوهای رسمی و فونت self-host فعلی جای asset گمشده را می‌گیرند. منبع اصلی مرجع است و در tsconfig/eslint/Tailwind ریشه از compilation فعال کنار گذاشته شده است. package و lockfile آن dependency/runtime فعال نیستند.

## فایل‌ها و کنترل رگرسیون

اجزای `src/components/preferred-template/`، CSS انتخابی، اتصال Store و basket، route مجاز profile، تاریخچهٔ حساب، هماهنگی بصری پنل، تنظیم exclude مرجع و تست `preferred-template.spec.ts` افزوده/به‌روز شدند. ادعای قدیمیِ «همهٔ کالاها نمونه‌اند» روی کارت واقعی اصلاح شد؛ برای کالای نمونه برچسب باقی است. metadata/noindex و خاموشی پرداخت تغییر نکردند. schema/migration یا seed جدیدی ساخته نشد و هیچ قیمت/stock/حساب واقعی حدس زده نشده است.

تست جدید بررسی می‌کند قالب روی مسیر اصلی واقعاً فعال است، جست‌وجوی هدر کار می‌کند، صفحهٔ عمومی API مدیریتی/قیمت/سفارش را نمی‌خواند، دکمهٔ تأیید همکار/پرداخت جعلی وجود ندارد، profile فقط یک h1 دارد و لینک‌ها واقعی‌اند، و مسیرهای home/profile/explore/wholesale/basket در عرض‌های360/390/768/1024/1280/1440 و تم/ناوبری موبایل کار می‌کنند. تست‌های قبلی دیدگاه، تیم/MFA، قیمت خصوصی و ثبت/لغو رزرو حذف نشده‌اند.

در بررسی بصری دسکتاپ/موبایل و تست، gutter منفی۱۸px رابط قدیمی با padding۱۲px قالب جدید تداخل داشت و۶px overflow ایجاد می‌کرد؛ margin فید و category-chips صریح reset شد، نه پنهان‌کردن overflow کل صفحه. انتظار polling تست جدید صرفاً برای settle شدن layout هنگام resize است؛ تست قبلیِ بررسی مستقیم عرض نیز حفظ شده است. فایل‌های screenshot در `.data` فقط بررسی محلی‌اند و وارد Git نمی‌شوند.

## ادامهٔ تکمیل FULL

ظاهر منتخب مبناست، نه ادعای تکمیل همهٔ امکاناتی که در prototype دکمه دارند. نقشهٔ F01..F16 در [گزارش۲۶](26-delivery-map.md) حفظ است. اولویت بعدی: مدیریت سفارش با مجوزهای مستقل، آدرس و مدل سیاست ارسال/مالیات، سپس پرداخت sandbox با revalidation؛ به‌موازات آن ماژول‌های واقعی CMS/استوری/دایرکت/مجله طبق قرارداد. provider، مبلغ ارسال، قانون مرجوعی و کلیدهای واقعی نباید جعل شوند. کامل‌شدن طراحی یک دکمه، به معنی متصل‌بودن سرویس آن نیست. استقرار دامنه، فروش/پرداخت واقعی و ممیزی مستقل انجام نشده‌اند.


اعتبارسنجی این تحویل: ۹۷backend،۱۲unit،۱۳E2E production (سه تست جدید قالب)،۱۱Python، lint/typecheck/build، Prisma validate، validator اسناد و npm audit --omit=dev با صفر آسیب‌پذیری گزارش‌شده موفق بودند. هیچ تست امنیتی مستقل یا تضمین ظرفیت تولید ادعا نمی‌شود.
